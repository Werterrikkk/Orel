# Уведомления в Telegram

Для демо достаточно отдельного бота и личного чата с ним. Публичный сервер, домен и webhook не нужны: приложение отправляет сообщения через исходящие HTTPS-запросы.

## Подключение

1. Открыть официального [@BotFather](https://t.me/BotFather), отправить `/newbot`.
2. Задать имя, например `orel · Контроль безопасности`, затем уникальный username, заканчивающийся на `bot`.
3. Скопировать выданный токен. В **orel → Уведомления** вставить его в поле **«Токен бота»** и нажать **«Проверить и подключить»**. В переписку с Codex токен присылать не нужно.
4. Нажать **«Открыть @…»**, затем **Start** в Telegram. Ответа не будет — это бот для уведомлений. Для группы сначала добавить бота и отправить в ней `/start`.
5. Вернуться в приложение, нажать **«Найти чаты»** и выбрать нужный. При необходимости ID можно ввести вручную.
6. Включить **«Отправлять события в Telegram»**, сохранить настройки и нажать **«Отправить тест»**. В выбранном чате должно появиться явно обозначенное тестовое сообщение.

Создание бота и обращение с токеном описаны в [официальной инструкции Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token). Бот не может первым начать личную переписку: сначала нужен Start от получателя.

Токен хранится только локально, в игнорируемом Git файле `data/runtime/telegram-secret.json` с правами 0600. API не возвращает его, поле очищается после подключения. При замене бота получатель и включение сбрасываются. Для остановки сообщений выключить переключатель и сохранить.

## Демонстрация

1. Во вкладке **«Видеонаблюдение»** включить превью.
2. В **«Зона и СИЗ»** выбрать обязательную экипировку. Жилет проверяется как обязательный, только если включён соответствующий флажок.
3. Снять каску и оставаться в кадре. Сначала приложение покажет перепроверку; после подтверждения появится жёлтый сигнал и придёт сообщение со снимком.
4. Если сигнал сохраняется 10 секунд наблюдения, придёт одно красное уведомление с актуальным кадром.
5. Надеть каску: после нескольких устойчивых наблюдений сигнал исчезнет.
6. Для запрещённого участка выделить опасную зону, сохранить и войти в неё. В сообщении будет её название и камера.

Подтверждение требует минимум 6 наблюдений с одной проблемой, не менее 2 секунд и 80% поддержки в окне 3 секунды. Красный отсчитывается от начала поддерживающего наблюдения, а не от момента отправки первого сообщения. Снятие сигнала требует минимум 3 наблюдения за 0,6 секунды.

Повторы одного типа/уровня в одной зоне отправляются не чаще раза в 30 секунд. Для повторного показа того же сценария подождать 30 секунд. Уровни СИЗ и опасной зоны независимы; история до включения не отправляется. Кадры отправляются только для событий, непрерывное видео — нет.

## Если сообщение не пришло

- Проверить переключатель и сохранённый чат. После Start повторить **«Найти чаты»**.
- Нажать **«Отправить тест»**. Проверить результат в приложении и сам чат, а не только состояние переключателя.
- Для группы убедиться, что бот добавлен и может отправлять сообщения/фото.
- В **«Последних отправках»** доступны очередь, успешная отправка и ошибки. Неподтверждённая доставка не повторяется автоматически, чтобы не создавать дубликаты.
- Сообщения старше 5 минут не догоняют пользователя после долгого отключения. Ожидающий жёлтый сигнал может быть заменён более актуальным красным.
- Если Telegram сообщает о другом polling-процессе/webhook, использовать отдельного бота для демо. Приложение не удаляет чужой webhook.

Для реальной проверки доставки нужны ваш бот и чат. Автоматические тесты не отправляют сообщения внешним пользователям. Временной фильтр уменьшает случайные пропуски, но не устраняет устойчивые ошибки модели; качество на реальной камере нужно проверить отдельно.
