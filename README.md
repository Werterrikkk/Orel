# orel

Видеонаблюдение для контроля опасных зон и средств индивидуальной защиты. Прототип для промышленного сценария «Интер РАО» в Орле.

Основной сценарий: открыть камеру, отметить запрещённый участок и видеть предупреждения прямо на видео. Целевой источник — Rubetek; для превью используется камера ноутбука и уже обученная YOLO26n.

## Версия v2 — 23 октября 2026

Новый экран оператора: тёмная палитра, янтарные акценты, видео и отдельная панель текущих тревог. История доступна в журнале и не подменяет текущие обнаружения.

Человек определяется отдельной исходной моделью YOLO26n COCO (`models/yolo26n.pt`), каска и жилет — дообученной PPE-моделью. Их результаты сопоставляются по геометрии. Это изменение алгоритма, а не новое обучение: качество на видео пользователя ещё требует проверки.

Тёмный (средняя яркость <18 из 255) или практически однородный кадр (стандартное отклонение <4) отмечается как неразличимый. Обнаружения очищаются сразу; через 5 секунд непрерывных свежих кадров создаётся одно событие камеры и передаётся обычной очереди Telegram, если уведомления включены. При восстановлении изображения контроль возобновляется. Потеря свежих ответов отдельно показывает отсутствие связи. Этот эвристический контроль не распознаёт все виды заслонения: текстурированная преграда может выглядеть как обычная сцена.

Четыре точки задают проекцию участка пола с перспективой, без измерения высоты или глубины. Старые прямоугольники читаются для совместимости. Сохранённая версия v1 остаётся под Git-тегом `orel-v1-recovery-3s`; изменения v2 выполняются в ветке `rebuild-v2`.

На этом Mac активны восстановленные веса `c64f9e1c7ce09ea1594cbb797f19ca3be3febc776597677904cdf18d4ae711db`, обученные локально 15 эпох; актуальный манифест `models/active.json`. Исторический раздел модели ниже описывает исходный опубликованный прототип.

## Что работает

- Вкладка **«Видеонаблюдение»** занимает всю рабочую область; есть отдельная кнопка полного экрана.
- Рамки подписаны: **«Человек»**, **«Каска»**, **«Жилет»**. После краткого исчезновения номер человека может восстановиться в течение 3 секунд по однозначному совпадению положения рамки. Отсутствующий человек не учитывается в текущем количестве, а подтверждение предупреждений после возвращения начинается заново.
- Опасная зона по четырём углам участка пола: нажать точки по порядку и сохранить. Проверка использует четырёхугольник, а не его прямоугольные границы. Входом считается любое пересечение рамки человека с четырёхугольником, включая касание границы.
- Каска и жилет проверяются во всём кадре; требования включаются отдельно.
- Предупреждения справа снизу: **«Наденьте СИЗ»** и **«Покиньте опасную зону»**. Жёлтый сигнал появляется после подтверждения: не менее 6 наблюдений, минимум 2 секунды и не менее 80% кадров с одной проблемой в окне 3 секунды. Красный — после **10 секунд наблюдения**, с повторной проверкой свежих кадров.
- У СИЗ и опасной зоны независимые таймеры. Исправление подтверждается минимум 3 наблюдениями за 0,6 секунды. Неразличимое изображение, смена настроек, потеря кадров и неоднозначное сопоставление рамок сбрасывают соответствующее подтверждение.
- Журнал со снимком, уровнями сигнала, фильтрами, отметкой оператора и CSV. Событие сохраняется только после подтверждения; переход в красный обновляет ту же запись.
- **Telegram**: подтверждённое событие и одно сообщение при красном уровне, с камерой, зоной, причиной, временем и снимком. Подключение — в разделе «Уведомления»; [инструкция по боту](docs/telegram.md).
- Настройки и журнал сохраняются между запусками. Микрофон не используется; непрерывная видеозапись не ведётся.

Фильтр подавляет кратковременные пропуски и дрожание границ. Устойчивую ошибку модели он не исправляет; полного отсутствия ложных срабатываний на реальной камере пока не подтверждено. Кратковременный номер рамки не устанавливает личность. Сопоставление соседних рамок по IoU не гарантирует непрерывный трекинг при перекрытии людей, быстрых движениях или плохом изображении.

## Запуск

На подготовленном ноутбуке:

```bash
./scripts/start.sh
```

Открыть [http://127.0.0.1:8127](http://127.0.0.1:8127), нажать **«Включить превью»** и разрешить доступ к камере. При необходимости разрешить камеру браузеру в настройках конфиденциальности macOS. Если уже запущена предыдущая версия, остановить её через `Ctrl+C` и запустить заново.

Голова и торс должны целиком попадать в кадр. В **«Зона и СИЗ»** выбрать обязательную экипировку, нажать **«Выделить на видео»**, отметить четыре угла по порядку и нажать **«Сохранить зону»**. По умолчанию включена каска, жилет можно добавить.

Браузер показывает живое видео и отправляет JPEG-кадры локальному серверу с целевой частотой до 5 кадров/с, без очереди. Первый запуск модели занимает несколько секунд. Фактическая частота зависит от компьютера. Для доступа к камере нужны localhost/127.0.0.1 либо HTTPS. Если браузер блокирует автопоказ, нажать **«Показать изображение»**.

При остановке, уходе в другую вкладку приложения или переходе страницы в фон камера отключается. Результаты старше двух секунд скрываются; неизвестное состояние не считается безопасным.

## Rubetek и обработка на камере

Целевая схема: на камере — модель и модуль аналитики, на рабочем месте — интерфейс оператора и журнал. Положение обработки отделено от правил зон и сигналов.

| Часть | Статус |
| --- | --- |
| Камера ноутбука → локальная YOLO26n → правила → интерфейс | Работает |
| Переносимые правила и контракт нормализованных обнаружений | Реализованы в `orel/surveillance.py`, `orel/domain.py`, `orel/sources.py` |
| Подключение к конкретному API/SDK Rubetek | Требуются модель камеры и документация |
| Экспорт/компиляция YOLO для ускорителя камеры и установка агента | Требуют аппаратуры, SDK и измерений на ней |

В официальном [руководстве RVX-4](https://support.rubetek.com/upload/iblock/50c/9u2c4eay1em5sx30bnn5us8ui86z21vn/RE-RVX_4.pdf) описаны RTSP и WebRTC. Наличие видеопотока и встроенной аналитики само по себе не подтверждает возможность загрузки собственной YOLO. Форма **«Камеры»** показывает Rubetek как ожидающий подключения источник. Приложение не имитирует успешное подключение.

## Установка и стек

React + TypeScript + Vite; Python + FastAPI; YOLO26n/OpenCV в отдельном процессе; SQLite и локальные снимки. Правила зон и эскалации используют только стандартную библиотеку Python.

Локальный прототип проверен на Mac с Python 3.13. Нужен Node.js 20.19+ либо 22.12+.

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.lock
uv pip install --python .venv/bin/python --no-deps -e .
npm --prefix frontend ci
npm --prefix frontend run build
# Перед включением камеры подключите локальные веса СИЗ — см. раздел «Модель».
./scripts/start.sh
```

Разработка: `./scripts/dev.sh`; интерфейс http://127.0.0.1:5173, API http://127.0.0.1:8127/docs. Один сервер и один оператор. Настройка нескольких камер и сетевой доступ с авторизацией — отдельный этап.

## Модель

В текущем эфире работают две модели: исходная YOLO26n COCO определяет людей, а локально дообученная YOLO26n — каски и жилеты. Активные веса СИЗ имеют SHA-256:

```text
c64f9e1c7ce09ea1594cbb797f19ca3be3febc776597677904cdf18d4ae711db
```

Модель дообучена на этом Mac 23 октября 2026 года: 15 эпох, Apple MPS, 799,81 секунды (13 минут 20 секунд). Очищенные выборки Construction-PPE: 1 029 / 131 / 141 изображение. На публичном тесте mAP50 = 0,8992, mAP50–95 = 0,5248. [Текущие метрики и происхождение](reports/model-recovery-evaluation.json), [подключение весов и воспроизведение обучения](docs/model.md). Отчёт [model-evaluation.json](reports/model-evaluation.json) относится к предыдущей модели от 21 октября и сохранён как история.

Метрики изображений не измеряют точность событий, трекинга или работу на предприятии. На общем плане возможны пропуски. Отсутствие найденной каски — повод проверить кадр; найденная каска не доказывает правильное ношение. Личность, персональный допуск и соблюдение всех правил безопасности не устанавливаются.

Веса, видео, датасеты и рабочая база не хранятся в Git. По умолчанию кадры остаются локально. Если включить Telegram, снимки подтверждённых событий отправляются выбранному чату через Telegram Bot API; непрерывный видеопоток туда не передаётся. Для camera-превью необходимы локальные веса СИЗ.

## Проверки и прежние данные

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check orel scripts tests
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

Для браузерных проверок нужны Google Chrome, WebKit (`cd frontend && npx playwright install webkit`), FFmpeg, подготовленный `data/demo.mp4` и тестовые фотографии Construction-PPE. Учебный ролик: `.venv/bin/python -m scripts.prepare_demo`. Chrome использует виртуальную камеру, WebKit — MediaStream из canvas; в обоих случаях распознавание выполняет настоящая модель. Это проверка программной цепочки, а не физической камеры, движения или качества на объекте.

Предыдущие записи, наряды и снимки не удаляются. API воспроизведения сохранён для совместимости; основной интерфейс теперь посвящён видеонаблюдению, зонам и СИЗ. [Архитектура](docs/architecture.md).

Результаты этой версии: [проверка видеонаблюдения](reports/surveillance-verification.json).

Проверка фильтра и уведомлений: [отчёт](reports/notifications-verification.json). Тесты Telegram используют подставной транспорт; реальная доставка проверяется вашим ботом через кнопку «Отправить тест».
